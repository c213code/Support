# Локальный агент по новым фичам

Пилот работает на ноутбуке: читает новые/изменённые тикеты **Support**, подбирает пакет знаний из `docs/knowledge/*/knowledge.json`, передаёт контекст и разрешённые файлы кода официальному Codex CLI, сохраняет черновик в `FeatureAgentDraft`. Дежурный видит результат на `/feature-agent`, выполняет предложенные SELECT самостоятельно и сам отправляет ответ. Бот ничего не пишет в Telegram и не меняет тикеты или базу `juz40`.

## Подготовка

На этом ноутбуке рабочее подключение хранится в `.env.feature-agent.local` (права 0600, файл исключён из Git). Миграция черновиков применена к базе Support. Для ручного запуска с этим подключением используйте `--env-file=.env.feature-agent.local` вместо `.env` в примерах ниже. На опубликованном сайте страница `/feature-agent` появится после деплоя обновлённого приложения.
Telegram-токен для чтения приложенных фото хранится в том же файле; получение фото не отправляет сообщений в чаты. Если часть фото не скачалась, агент получает явную отметку об этом и запрашивает скриншот, когда он необходим для вывода.

1. Подключить `DATABASE_URL` к той **Support**-базе, на которой работает сайт. Старый локальный дамп даст черновики только для старых локальных тикетов. Для production нужен отдельный доступ с правами читать `Issue`, `TelegramMessage`, `IssueSubmission` и писать только `FeatureAgentDraft`.
2. Применить миграцию `20261010030000_feature_agent_draft` к выбранной базе обычным процессом деплоя. Для локального теста можно использовать `npx prisma migrate deploy`, предварительно убедившись, что `prisma.config.ts` указывает на локальную БД.
3. Указать `FEATURE_AGENT_CODE_ROOT=/путь/к/juz40` — это исходники только для чтения. Рабочие `.env` и конфиги из `juz40` агенту не передаются: в отдельный временный каталог копируются лишь `.java`/`.sql` из `src/main`, указанные в пакетах знаний.
4. Официальный CLI берётся из приложения ChatGPT/Codex. Если путь отличается, задать `FEATURE_AGENT_CODEX_BIN`; обычная команда `codex` в PATH этого ноутбука относится к другому Python-приложению. Требуется авторизация Codex и интернет.

Модель пилота закреплена: `gpt-6-luna`, reasoning `medium`. Для смены добавьте в env-файл `FEATURE_AGENT_MODEL` и `FEATURE_AGENT_REASONING`, например `FEATURE_AGENT_MODEL=gpt-5.6-terra`. Автоматического перехода на более дорогую модель нет. Medium задаёт глубину рассуждений, а не жёсткий бюджет токенов; ограничение очереди в 20 разборов в день действует отдельно.

Пример разового разбора уже существующего тикета:

```bash
node --env-file=.env --import tsx scripts/local-feature-agent.ts once <issueId>
```

Наблюдение за новыми кейсами (команда работает, пока запущена и ноутбук не спит):

```bash
node --env-file=.env --import tsx scripts/local-feature-agent.ts watch
```

После успешной разовой проверки и подключения к **той же базе, что у сайта**, можно включить запуск при входе в macOS:

```bash
node --import tsx scripts/feature-agent-service.ts install /абсолютный/путь/к/support.env
node --import tsx scripts/feature-agent-service.ts status
```

Остановить агент: `node --import tsx scripts/feature-agent-service.ts stop`. Лог находится в `.local-feature-agent/worker.log`. Установка создаёт LaunchAgent в `~/Library/LaunchAgents`, но не разворачивает программу на сервере; при выключенном или спящем ноутбуке новые кейсы не обрабатываются.

При первом `watch` курсор ставится на текущий момент: старые тикеты массово не отправляются модели. После перезапуска курсор из `.local-feature-agent/state.json` позволяет догнать новые изменения, пришедшие, пока ноутбук был выключен. `FEATURE_AGENT_POLL_SECONDS` задаёт интервал опроса, минимум 15 секунд, по умолчанию 60. Ошибка анализа отображается в Support и не останавливает очередь; конкретный тикет можно повторить командой `once`.
До запуска Codex worker отбирает обращения по `routing` подключённых пакетов. Несвязанные тикеты пропускаются с продвижением курсора, без запуска модели и расхода дневного лимита. `watch` разбирает максимум 20 подходящих тикетов в день; `FEATURE_AGENT_DAILY_LIMIT` меняет лимит, остаток очереди ждёт следующего дня.

## Подключение новой фичи

Для каждой новой фичи добавьте проверенные правила, инструкцию и SELECT-шаблоны в отдельный каталог `docs/knowledge`. В `knowledge.json` задайте `routing: { "enabled": true, "any": [...], "all": [[...]] }`. `any` содержит специфичные фразы (достаточно одной), `all` — альтернативные наборы признаков (нужны все фразы одного набора). Слова сравниваются целиком; `*` в конце слова разрешает окончания на русском и казахском. Общие слова вроде «курс», «ошибка», «нет доступа» отдельно не подходят для маршрутизации.

Пакеты без `routing.enabled: true` не подключаются к автоматическим подсказкам. Worker перечитывает пакеты при каждом опросе; сайт получает их при деплое. На `/feature-agent` видны только черновики по подключённым фичам с правилом из текущего пакета. `no_match` и ответы без подтверждённого правила скрыты, включая уже сохранённые карточки. Для фото без содержательной подписи нужен текст о действии/фиче: маршрутизация перед моделью использует описание и текст сообщений, а снимки читает ИИ после отбора. `once` использует тот же фильтр.

Для больших backend-файлов задайте в источнике правила `line` и `end_line`:
worker передаст только эти диапазоны с исходными номерами строк. Перекрытия объединяются;
если тот же файл нужен другому правилу целиком, сохраняется прежний режим полной копии.
Допускается исходный файл до 2 MB для фрагментов, фрагмент до 300 KB. Диапазоны
проверяются на границы файла. У Daily Streak таким образом передаются только запросы
открытых/выполненных уроков и счётчиков куратора, а не огромные репозитории целиком.

## Границы пилота

На странице `/feature-agent` переключатель «Локальный агент» сохраняет разрешение на обработку в базе Support. Выключение останавливает новые разборы, текущий завершается. Курсор остаётся на месте: после включения агент продолжит очередь в пределах дневного лимита. Команда `once` остаётся ручным разбором и выполняется независимо от переключателя.

Worker сообщает состояние каждые 30 секунд, даже во время разбора и при выключенном переключателе. После двух минут без связи сайт показывает «Ноутбук не на связи». Включение переключателя на сайте не запускает программу на выключенном ноутбуке; на нём должен быть установлен LaunchAgent. Для переключателя требуется миграция `20261010050000_local_feature_agent_control`; новый ненастроенный worker по умолчанию выключен.

- Подключены Commerce V2 (`commerce-v2`) и Daily Streak / «Менің Жұлдызым» (`daily-streak-v1`). Другие фичи требуют своего проверенного пакета и маршрутизации; если модель не находит подходящего правила, карточка не показывается. В Daily Streak явно отмечено расхождение воскресной нормы между PDF и текущим локальным DV-8305: версия production требует подтверждения.
- Тексты перед моделью маскируют почты, телефоны и секреты. Фото передаются модели как вложения и могут содержать персональные данные; учитывайте это при работе с реальными обращениями.
- Codex работает с копией файлов кода, а не с развёрнутым production. В черновике нельзя объявлять платежи, группы и заявки подтверждёнными без результата SELECT. Даже имея доступ к БД Support, дочерний процесс Codex получает окружение **без** `DATABASE_URL` и токена Telegram.
- Получение кейсов напрямую из Telegram и отправка черновика в личку дежурному — следующий этап. Сейчас источником служат тикеты сайта Support, а результат показывается на `/feature-agent`.
