# Чат автоотчёта

В окне «Авто-репорт» дежурный пишет результат работы: например,
«Мини тест решён», затем может уточнить «кроме математики».
ИИ проверяет все открытые обращения выбранной области, объясняет соответствие
и предлагает статусы. Кнопка «Применить отмеченные» выполняет изменения через
общий сервис статусов с историей событий и существующими уведомлениями.

## Поток данных

1. `AutoReportChat` передаёт сообщение, область и ID предыдущего запуска.
2. Авторизованный `POST /api/reconcile` проверяет вход. `startRun` загружает
   историю предыдущего запуска только того же автора за ту же дату. Новый
   запуск сохраняет неизменяемый снимок указаний и версий тикетов.
3. Существующий пошаговый исполнитель `useAutoReportRun` вызывает `stepRun`.
   Адресный запуск не объединяется с обычным разбором дня. Тикеты выбираются
   без текстового фильтра: опечатка или казахская формулировка не исключает
   обращение до проверки моделью.
4. `reconcileIssue` получает описание, группу, дату, переписку и указания.
   Правила адресного разбора из `reconcileChat.ts` используются вместо правил обычного разбора
   для всех существующих провайдеров. Даже без reply в Telegram
   указание дежурного может подтвердить общий результат.
5. Статус вне темы, неоднозначность и исключения дают `UNCLEAR`. Применимый
   ответ должен содержать точную цитату из указаний; сервер проверяет её.
   Это проверка происхождения цитаты, а не гарантия семантической точности.
   Человек видит причину и может снять отметку перед применением.
6. `applyVerdicts` вызывает `changeIssueStatus` с ожидаемыми статусом и
   `updatedAt`. Условное обновление тикета и запись события атомарны.
   Изменённые за время разбора тикеты пропускаются.

## Область и история

- «За день» в чате — открытые тикеты именно выбранного дня.
- «Все открытые» — все нерешённые тикеты до выбранной даты включительно,
  без ограничения последней неделей. Уже решённые не переоткрываются.
- Обычный разбор дня сохраняет прежнюю выборку с переносом активных обращений.
- История содержит до 8 сообщений по 2000 символов. При достижении лимита
  нужно начать новый диалог: исходные исключения не обрезаются молча.
- Контакты маскируются перед сохранением указаний и передачей модели.
- Чат сохраняется в запусках разбора; остановленный разбор можно продолжить.

## Проверки и выпуск

Миграция: `20261006090000_reconcile_chat`. Её нужно применить перед запуском
обновлённого приложения; штатный build проекта уже выполняет migrate deploy.

Локальные проверки без сети и записи в базу:

```sh
npx tsx --test scripts/reconcile-chat.test.ts
npx tsc --noEmit
npx prisma validate
```

Семантическая проверка на синтетических примерах через настроенную модель
(читает словарь проекта, расходует квоту провайдера, не меняет тикеты):

```sh
npx tsx --env-file=.env scripts/eval-reconcile-chat.ts
```
