# DV-7952: Доступ к урокам после просмотра лекций (сводная документация)

Jira: https://juz.atlassian.net/browse/DV-7952 — «Доступ к урокам после просмотра лекций»,
исполнитель Daulet Zhantekov, статус In Progress (на 2026-10-01). В Confluence страницы нет.
Код фичи влит в `master` (ветка `release/DV-7952`, merge `e6469c4829`; фильтр «только лекции» — `0499ab052c`).

## 1. Суть

Пока ученик не прошёл все общие теоретические уроки недели (лекции с `TEORIYALYK_TAPSYRMA`),
выбранные типы заданий этой недели закрыты — в том числе ОСТ-подобные тесты. Фича включается
на уровне курса. Тикет объединяет три части:

| Часть | Что делает | Подробности |
| --- | --- | --- |
| Weekly theory gate | Замок на задания недели до завершения теории | разделы 2–6 |
| Флаги в streak/трекере | `weeklyTheoryLocked` в ежедневной цели и календаре | раздел 7 |
| Дедлайны лекций | Опциональный дедлайн лекции, время первого завершения | раздел 8 |

## 2. Правило доступа

Все опубликованные, неудалённые, общие, корневые уроки `LECTURE` с `ratingTaskType = TEORIYALYK_TAPSYRMA`
в том же курсе, месяце и неделе должны иметь неудалённый итоговый (total) прогресс `SUCCESS`
у этого студента и группы.

| Случай | Результат |
| --- | --- |
| Замок выключен, список целей пуст/не задан, теории нет | Старые правила доступа |
| Теория другой недели или месяца | Игнорируется |
| Персональная / куратора / дочерняя / неопубликованная / удалённая теория | Не блокирует |
| Урок другого типа с тем же `ratingTaskType` (не `LECTURE`) | Не блокирует |
| Нерейтинговая лекционная теория (`is_rating=false`) | Всё равно обязательна |
| Несколько теоретических уроков | Нужен `SUCCESS` по каждому |
| Теория случайно в списке закрываемых типов | Сама никогда не закрыта |
| `null` в массиве целей | Цель остаётся открытой по старым правилам |

Порядок проверки при прямом доступе: родитель/старт → замок недели → создание прогресса.
Приоритет старых ошибок сохранён; замок даёт локализованную 400 `weekly_theory_gate_locked` (EN/RU/KK).
Тема цели определяется по порядку: общая тема → персональная модификация студента/группы →
модификация куратора для группы. Детальная проверка читает master-БД (чтобы не пускать по устаревшей реплике).

## 3. Настройки курса и миграции

- Таблица `courses`: булево `weeklyTheoryGateEnabled` и массив `weeklyTheoryGatedRatingTaskTypes` (`varchar[]`).
- Настройки только в БД, CRUD/API курса вне скоупа.
- Миграция 001 добавляет колонки (выключено/пусто), 002 включает фичу для ещё не настроенных
  курсов SMART/JUNIOR/TURBO с целями `INTERACTIVE_BEINE`, `UY_ZHUMYSY`, `UZH_KZH`, `KUIZ_TEST`.
- При первом назначении потока применяются текущие дефолты (в них есть и `PRAKTIKALYK_SABAK`);
  дублирование курса сохраняет настройки источника.
- Откат: выключить флаг у курса. Предикат отката 002 широкий и может задеть вручную настроенные
  курсы — сначала проверить затронутые строки.

## 4. API

| Актор | Метод/путь | Изменение |
| --- | --- | --- |
| Student | `GET /v2/student/groups/{groupId}/lessons` | `weeklyTheoryLocked` у уроков и детей |
| Student | `GET /v1/student/groups/{groupId}/lessons/search` | `weeklyTheoryLocked` в результате |
| Student | существующие детали урока | проверка доступа до создания прогресса, 400 при замке |

`weeklyTheoryLocked` — non-null boolean; true только когда старые условия старта/родителя уже
выполнены. Поле аддитивное, обратно совместимое; Swagger-группа Student. В поиске null-флаги
легаси-проекции мапятся в false через `LessonSearchResultMapper`.

## 5. Транзакции и кеш

1. `ProgressService` (все четыре пути сохранения: `createProgress`/`save`/`saveAndFlush`/`saveAll`)
   публикует `WeeklyTheoryProgressChangedEvent` внутри транзакции записи.
2. Публикатор `WeeklyTheoryProgressEventPublisher` сам решает, релевантен ли урок (только
   `LECTURE` + `TEORIYALYK_TAPSYRMA`) и фиксирует ID/месяц/неделю.
3. После коммита `WeeklyTheoryGateCacheInvalidationListener` точечно сбрасывает ключи недели и
   поиска через WRITE cache manager, без сканирования Redis. При откате сброса нет.
4. Ошибка сброса логируется и не откатывает прогресс; устаревшее лечится TTL 10 минут.
   После выкладки правил старые закешированные списки живут до TTL, прямой доступ — сразу актуален.
5. Пересчёты оценок/массовые записи не публикуют streak-события.

## 6. Стоимость запросов и ограничения

- Списки (месяц/неделя и поиск) агрегируют теорию один раз на неделю (CTE); выключенные курсы
  пропускаются; ranged-эндпоинт ограничен запрошенным месяцем/неделей.
- Для каждой цели считается один переиспользуемый предикат `weeklyTheoryBlocked`.
- Поиск находит родителя ребёнка по реальному `parent.id`.
- Главный риск — нативные запросы в `LessonRepository`. Планы на данных preprod не проверены.

Фронтенд: сайдбар перечитывает список и активный поиск после смены статуса; нижняя навигация
использует единый disabled-предикат, `weeklyTheoryLocked` приоритетнее собственного `SUCCESS`;
для закрытого ребёнка показывается модалка без редиректа на родителя.

## 7. weeklyTheoryLocked в streak и трекере

- `GET /v1/student/streak` → `dailyGoal.items[].weeklyTheoryLocked`.
- `GET /v1/student/calendar/day` → у уроков `weeklyTheoryLocked`.
- Флаг считается тем же каноническим предикатом (`LessonRepository.WEEKLY_THEORY_LOCKED_QUERY`),
  не меняет счётчики цели и авторизацию (проверка доступа продолжает отклонять запросы).
- В пул подходящих типов ежедневной цели добавлен `LECTURE`.
- Старые записи цели в кеше дают `false` до 5-минутного TTL или события завершения работы.

## 8. Дедлайны лекций (часть DV-7952)

- Лекция может иметь опциональный дедлайн через `PUT /v1/lessons/lectures/{lectureId}`:
  `withDeadline` (boolean) и `deadline` (ISO date-time).
- Выключение дедлайна очищает дату. `withDeadline=true` без даты: ошибка `deadline_is_null`
  уже при сохранении (bean validation в `LectureLessonDto`), и при публикации.
- Дублирование копирует оба поля. Дедлайн информационный: доступ к видео/мини-тесту и баллы не меняются.
- Первое завершение видео пишет `finishTime` (UTC); повторный просмотр его не меняет.
- Миграция `db/changelog/2026/10/02/001-JUZ40-reset-lecture-deadlines.sql` сбрасывает флаг/дату
  только у строк `lesson_type = 'LECTURE'` (включая удалённые, персональные и куратора).
  Порядок выкладки: остановить запись лекций на старых нодах → миграция + бэкенд → фронт.
  Повторно миграцию после того, как пользователи задали дедлайны, не запускать.
